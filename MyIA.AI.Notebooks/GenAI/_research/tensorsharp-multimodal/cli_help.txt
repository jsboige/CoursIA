Usage: TensorSharp.Cli --model <path.gguf> [options]

Runs local LLM inference from the terminal: single-shot generation, interactive chat,
multimodal input (image/audio/video/PDF), JSONL batches, image editing, and benchmarks.
Options may also come from a JSON file via --config (command line wins).

Model and prompt input:
  --model <path>
      GGUF model to load. Required for every mode except --list-gpus and --test-templates. Quantized
      (e.g. Q8_0, Q4_K_M) and F16/BF16 GGUFs are supported; the architecture is read from the file.
      Default: none.
      Example: --model gemma-4-E4B-it-Q8_0.gguf
  --input <file>
      UTF-8 text file with the prompt. Default: a built-in demo prompt ("What is 1+1?"); when an
      image/audio/video is attached without --input, a matching "describe this ..." prompt is used.
      Example: --input prompt.txt
  --system <text>
      System prompt for the conversation. Default: none (the model's own template default applies).
      Example: --system "You are a terse assistant."
  --system-file <path>
      Read the system prompt from a UTF-8 text file instead of the command line. Default: none.
      Example: --system-file persona.txt
  --pdf <file>
      PDF document input. A born-digital PDF has its text layer extracted and inlined into the
      message (no truncation); a scanned/image-only PDF is rendered to page images and needs a
      vision-capable model (see --mmproj). Combine with --input to ask a question about the
      document. Default: none.
      Example: --pdf report.pdf --input question.txt
  --tools <file>
      JSON file with an array of tool/function definitions to expose to the model (function
      calling). Default: none.
      Example: --tools tools.json
  --think
      Enable the model's thinking/reasoning mode on architectures that support it (e.g. Qwen3/3.5,
      Gemma 4). Default: off.
      Example: --think
  --max-tokens <N>
      Maximum number of tokens to generate. Range: >= 1. Default: 100.
      Example: --max-tokens 1024
  --output <file>
      Write the generated text to a file instead of stdout (for Qwen-Image-Edit: the output image,
      default edited.png). Default: print to stdout.
      Example: --output answer.txt

Multimodal input (vision / audio / video models):
  --image <file>
      Image input for a vision model (PNG/JPEG/...). Repeatable: for Qwen-Image-Edit each extra
      --image adds a source picture the prompt can reference as "Picture 1", "Picture 2", ...
      Default: none.
      Example: --image photo.jpg
  --audio <file>
      Audio input for an audio-capable model (e.g. Gemma 4). Default: none.
      Example: --audio speech.wav
  --video <file>
      Video input: frames are extracted and fed to the vision encoder. Default: none.
      Example: --video clip.mp4
  --mmproj <path>
      Multimodal projector (vision/audio encoder) GGUF that pairs with the model. Default:
      auto-detected next to the model for known architectures (gemma3/gemma4, Qwen3.5, Mistral3,
      Nemotron); pass it explicitly for anything else.
      Example: --mmproj mmproj-gemma-4-E4B-it-Q8_0.gguf

Compute backend and GPUs:
  --backend <type>
      Compute backend: cpu, cuda (direct CUDA), mlx (Apple), ggml_cpu, ggml_metal, ggml_cuda, or
      ggml_vulkan. Default: ggml_cpu.
      Example: --backend ggml_cuda
  --gpu-device <N>
      Vulkan device index for the ggml_vulkan backend on multi-GPU hosts (e.g. an integrated Intel
      GPU next to a discrete NVIDIA one). Range: >= 0 (see --list-gpus). Default: 0
      (TS_GGML_VULKAN_DEVICE env var overrides).
      Example: --backend ggml_vulkan --gpu-device 1
  --list-gpus
      List the Vulkan devices ggml-vulkan can see (index + adapter name) and exit. No model needed.
      Example: --list-gpus

Tensor parallelism (multi-GPU):
  --tp <N>
      Split the model across N GPUs on this machine (tensor parallelism): each GPU holds 1/N of
      every weight and the shards cooperate on every token. Use it when a model does not fit on one
      GPU. Range: 1 to the number of local GPUs. Applies to the cuda, ggml_cuda, and ggml_vulkan
      backends. Multi-GPU is implemented PER ARCHITECTURE, not per backend, and in two forms.
      Architectures that shard weights run true tensor parallelism. qwen4exp (Qwen3.8-Flash-Next)
      shards nothing, so --tp N runs it as a LAYER SPLIT instead - each GPU holds a contiguous run
      of whole layers, which is the same and only multi-GPU mode llama.cpp offers for it. That is a
      CAPACITY feature: it lets a model, context or resident-weight set that one GPU cannot hold fit
      across several, and is not expected to raise tok/s. The startup line says which mode actually
      ran. An architecture that supports neither says so on stderr and runs on one GPU rather than
      silently leaving the others idle. Default: 1 — no splitting (TENSORSHARP_TP_DEGREE env var
      overrides).
      Example: --backend ggml_cuda --tp 2
  --tp-node-id <N>
      This node's 0-based ID for multi-node (distributed) tensor parallelism over TCP. Node 0 is the
      driver that owns sampling and prints the output; every other node runs a worker loop that
      mirrors the driver. Requires --tp-peers. Range: 0 to (number of nodes - 1). Default: none —
      single-node.
      Example: --tp 2 --tp-node-id 0 --tp-peers 192.168.1.10:9500,192.168.1.11:9500
  --tp-peers <list>
      Comma-separated host:port list of ALL nodes in the distributed TP cluster, ordered by node ID;
      every node passes the identical list. Requires --tp-node-id. Default: none.
      Example: --tp-peers 192.168.1.10:9500,192.168.1.11:9500

Sampling (batch runs are greedy; interactive chat samples - see below):
  --temperature <f>
      Sampling temperature: 0 = greedy (always the most probable token), higher = more random.
      Typical range: 0.0-2.0. Default: 0 for one-shot/batch runs, 0.8 for --interactive (overridden
      by the model's own general.sampling.temp when the GGUF ships one). Greedy chat degenerates
      into endless repetition on long answers, which is why --interactive does not default to it.
      Example: --temperature 0.7
  --top-k <N>
      Keep only the K most probable tokens; 0 disables the filter. Typical range: 20-100. Default: 0
      for one-shot/batch runs, 40 for --interactive (or the GGUF's general.sampling.top_k).
      Example: --top-k 40
  --top-p <f>
      Nucleus sampling: keep the smallest token set whose cumulative probability exceeds P; 1.0
      disables. Range: 0.0-1.0. Default: 1.0 for one-shot/batch runs, 0.95 for --interactive (or the
      GGUF's general.sampling.top_p).
      Example: --top-p 0.9
  --min-p <f>
      Drop tokens whose probability is below min-p x the top token's probability; 0 disables. Range:
      0.0-1.0. Default: 0 for one-shot/batch runs, 0.05 for --interactive.
      Example: --min-p 0.05
  --repeat-penalty <f>
      Multiplicative penalty on recently generated tokens; 1.0 = none, > 1.0 discourages repetition.
      Typical range: 1.0-1.5. Default: 1.0.
      Example: --repeat-penalty 1.1
  --penalty-last-n <N>
      How many of the most recent tokens the repeat/presence/frequency penalties consider; 0
      disables history penalties, -1 uses the whole history. Default: 64.
      Example: --penalty-last-n 128
  --presence-penalty <f>
      Additive penalty on any token that has already appeared; 0 disables. Typical range: 0.0-2.0.
      Default: 0.
      Example: --presence-penalty 0.2
  --frequency-penalty <f>
      Additive penalty proportional to how often a token has appeared; 0 disables. Typical range:
      0.0-2.0. Default: 0.
      Example: --frequency-penalty 0.3
  --seed <N>
      Random seed for reproducible sampling; -1 = non-deterministic (time-based). Default: -1.
      Example: --seed 42
  --stop <text>
      Stop sequence: generation halts when this string is produced (the string itself is not
      emitted). Repeat the flag for several. Default: none (the model's EOS token always stops).
      Example: --stop "</s>" --stop "<|eot|>"

Speculative decoding:
  --spec | --no-spec
      Enable/disable speculative decoding: a drafter proposes the next few tokens and the trunk
      verifies them in ONE batched forward. Every emitted token still comes from a trunk row, so
      this is a speed path only - the output is what plain decoding would have produced. Engages on
      --input, --input-jsonl, --multi-turn-jsonl and --interactive. Must be passed BEFORE the model
      loads (it is what tells glm-dsa to page its ~3 GiB NextN layer into VRAM, which also leaves
      less room for the context). Not available under --tp N>1 on a checkpoint whose draft block
      borrows the trunk's LM head, which includes GLM-5.2. Accepted as --mtp-spec / --no-mtp-spec
      too. Default: off; env TS_SPEC (or TS_MTP_SPEC; glm-dsa also honours TS_GLM_MTP=1/0, which
      overrides both).
      Example: --model GLM-5.2-UD-IQ2_XXS-00001-of-00006.gguf --backend ggml_cuda --spec --chat
  --spec-type <name>
      Which speculation ALGORITHM to draft with. 'auto' (default) uses whatever drafter the
      checkpoint carries: a per-token NextN/MTP head (GLM-5.2, Qwen 3.6, Gemma 4's separate
      assistant GGUF) or a block drafter (DeepSeek V4 DSpark, DFlash / DFlash2 on Muse-Glimmer and
      Qwen 3.8). 'draft-head' and 'block' pin one of those explicitly. 'ngram' needs NO trained
      weights at all - it drafts by finding where the last few tokens occurred earlier in the
      context and proposing what followed, so it works on every model and is strong on summarizing,
      editing, translating, repetitive structured output and agentic loops, where the answer quotes
      the prompt. Env: TS_SPEC_TYPE.
      Example: --spec --spec-type ngram --spec-draft 8
  --spec-draft <N>
